# Yorimiyu: архитектура памяти и агентов

## Проверенная граница интеграции

Letta Code (vendor/letta-code) — самостоятельный агентный CLI, не Python-библиотека Graphiti. По исходному README он имеет собственные memory blocks, MemFS, субагентов и backend (cloud/local). Graphiti (vendor/graphiti) — Python-фреймворк временного графа, которому нужны графовая БД, LLM и embeddings. Объединение требует явного адаптера и согласованной модели идентичности агента.

Реализованный первый слой: `memory_bridge.py` хранит агентов и ручные записи памяти в локальной SQLite, `launcher.py` предоставляет loopback JSON API, `web/app.js` показывает реальные записи. Это **не** Letta-agent runtime, не граф Graphiti и не автоматическое обучение.

## Следующий интеграционный контракт

1. Агент Yorimiyu: UUID и явная привязка к Letta agent ID; без автоматического исполнения кода.
2. Событие памяти: id, agent_id, source, timestamp, content, provenance; запись в Graphiti только через отдельную очередь с повторными попытками и идемпотентностью.
3. Graphiti: отдельный сервис на localhost, Neo4j/FalkorDB, ключи и embeddings в локальном конфиге вне Git. Отдельный endpoint поиска и визуализации с лимитами.
4. Letta: управляемый процесс с подтверждением опасных инструментов, отдельными credentials и безопасной остановкой. Не запускать пользовательские команды из веб-API напрямую.
5. UI: показывать состояние каждого сервиса из фактической проверки, а не по наличию исходников.

## Безопасность

HTTP привязан только к 127.0.0.1. Запись API требует JSON, Origin/Host ограничены loopback; это локальный интерфейс, **не** сервис для публичной сети. SQLite находится в исключённой из Git папке `.runtime`. Данные и секреты нельзя коммитить. Резервные копии, аутентификация для удалённого доступа и аудит ещё не реализованы.
