# Yorimiyu: Cloud.ru + локальная Neo4j

## Подключение
1. Установите Docker Desktop с WSL2. В PowerShell задайте **собственный** пароль Neo4j: `$env:YORIMIYU_NEO4J_PASSWORD="YOUR_STRONG_PASSWORD"`.
2. В корне проекта выполните `docker compose -f docker-compose.neo4j.yml up -d`. Neo4j доступна только на 127.0.0.1; данные находятся в `data/neo4j`.
3. В той же сессии PowerShell запустите `./Yorimiyu.bat`. Пароль Neo4j задаётся локально через переменную среды; **не записывайте его в Git**.
4. В разделе «Подключения» укажите HTTPS OpenAI-совместимый endpoint Cloud.ru, ID модели и ключ. Настройки сохраняются в `data/cloudru-settings.json` на компьютере; убедитесь, что папка `data` исключена из Git.
5. Выберите агента. Новые записи памяти индексируются в Neo4j автоматически, если база доступна. Для старых записей нажмите «Индексировать память».
6. Для резервной копии SQLite нажмите «Создать копию». Восстановление заменяет содержимое SQLite и требует подтверждения.

## Ограничения
- Для Neo4j нужен Docker Desktop; BAT не устанавливает Docker и не запускает Neo4j автоматически. Команда `docker compose ... up -d` запускает локальную службу.
- Автоматическое извлечение сущностей использует консервативные шаблоны имён, а не полноценную модель извлечения Graphiti. Graphiti остаётся отдельным необязательным интеграционным модулем.
- Графовая БД не входит в резервные копии SQLite. Перед восстановлением/переносом Neo4j делайте отдельный согласованный бэкап её тома.
- Cloud.ru — удалённый сервис; сообщения, передаваемые модели, выходят за пределы компьютера. API-ключ никогда не возвращается браузеру после сохранения.
- Не используйте публичный доступ к локальному REST API. Настройки Cloud.ru и резервные копии содержат чувствительные данные.
